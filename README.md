# 주요정보통신기반시설(주통기) 기술적 취약점 진단 — Linux · Windows

KISA **『주요정보통신기반시설 기술적 취약점 분석·평가 상세가이드』** 기준으로 리눅스·윈도우 서버를 **스크립트로 자동 점검**하고, 취약 항목을 직접 **조치·재점검**한 프로젝트입니다.

> EST 인프라보안 과정 3차 개별 프로젝트 · 점검 대상: 자체 구축 랩(ESXi) 서버 (2인 수행 — 리눅스 / 윈도우)

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| **점검 기준** | KISA 주통기 기술적 취약점 분석·평가 상세가이드 (Linux U-코드 / Windows W-코드) |
| **점검 대상** | Rocky Linux 10.2 (MASTER·SLAVE, keepalived+haproxy 이중화) · Windows Server 2022 |
| **점검 방식** | 스크립트 자동 점검(읽기 전용) → 양호/취약 자동 판정 → 수동 검증(오탐 제외) → 조치 → **재점검** |
| **점검 범위** | 계정 / 파일·디렉터리 / 서비스 / 패치 / 로그 / (윈도우) 보안 관리 |

## 3. 자동화 스크립트 구성

### Linux — Bash (`.sh`)

| 스크립트 | 점검 범위 |
|---|---|
| `scripts/linux/Account_check.sh` | 계정 관리 (U-01~U-06, 상 위주) |
| `scripts/linux/File_check.sh` | 파일·디렉터리 관리 (U-14~U-30, 상 위주) |
| `scripts/linux/Service_check.sh` | 서비스 관리 (U-34~U-63, 전체) |
| `scripts/linux/Rest_check.sh` | 보완 점검 — 잔여 항목 (계정 U-07~13 / 파일 U-28~33 / 로그 U-65~67) |

> 패치 관리(U-64)는 폐쇄망에서 `dnf` 저장소 접근이 불가해 **수동 점검**으로 처리했습니다(스크립트 미포함). 윈도우 패치(W-27)는 `Get-HotFix` 기반으로 `Check-D-System.ps1`에 포함되어 있습니다.

### Windows — PowerShell (`.ps1`)

| 스크립트 | 점검 범위 |
|---|---|
| `scripts/windows/Check-A-Account.ps1` | 계정·로컬 보안 정책 (W-01~15, 47~57, 59, 60) |
| `scripts/windows/Check-B-File.ps1` | 공유·파일 권한 (W-16, 17, 23, 43, 46, 58, 61) |
| `scripts/windows/Check-C-Service.ps1` | 네트워크·서비스 (W-18~34, 36, 44, 64) |
| `scripts/windows/Check-D-System.ps1` | 패치·로그·시스템 (W-27, 35, 37~42, 45, 62, 63) |

> **공통 설계**: 점검 1건을 `chk()`(Bash) / `Chk`(PowerShell) 헬퍼로 실행해 **양호·취약·수동확인·해당없음**을 자동 판정하고, 색상 출력 + CSV 저장. **읽기 전용**(설정 변경 없음)이라 조치 전·후 두 번 실행해 개선 효과를 검증합니다.

### 사용법

```bash
# Linux (sudo 권장)
sudo bash scripts/linux/Account_check.sh      # 결과: /root/check/log/*.csv
```

```powershell
# Windows (관리자 PowerShell)
powershell -ExecutionPolicy Bypass -File .\scripts\windows\Check-A-Account.ps1   # 결과: C:\check\log\*.csv
```

> **점검 전략**: 위험도 **'상' 항목을 분야별로 우선 점검·조치**한 뒤 잔여 항목(중·하)을 보완 점검하는 2단계 방식. 실무의 "고위험 우선 → 전체 확장" 흐름을 반영했습니다.

## 4. 오탐(False Positive)·수동확인 처리 — 자동화의 한계 보완

자동 점검 결과를 그대로 신뢰하지 않고 **수동 검증으로 바로잡았습니다.**

### Linux 오탐 5건

| 분야 | 오탐 | 처리 방식 |
|---|---|---|
| 파일 U-15 | 소유자 없는 파일 = 컨테이너 레이어 | 스크립트에서 `containerd` 경로 제외 |
| 파일 U-24 | 심볼릭 링크 권한 | `-type f`로 링크 제외 |
| 파일 U-26 | `/dev/shm` 공유메모리 | `/dev/shm` 경로 제외 |
| 서비스 U-42 | rpcbind = NFS 의존 서비스 | NFS 구동 시 양호로 판별 |
| 서비스 U-47 | 메일 relay 내부망 제한 | 실제 적용값(`postconf`) 기준 판별 |

### Windows 수동확인·보완

- **수동확인 판정**: `$null`로 표시되는 항목(W-03 불필요 계정, W-19 IIS 사용 목적, W-37 예약 작업 등)은 서버 상황을 직접 검토해 양호/취약 판정.
- **재부팅 후 재검증**: W-44(원격 레지스트리)는 최초 점검 시 중지였으나 시작 유형이 '자동'이어서 **재부팅 후 Running 확인 → 취약**으로 보정.

→ 이 저장소의 스크립트는 **오탐 판별·수동확인 로직이 반영된 개선 버전**입니다.

## 5. 이중화(HA) 환경 고려

리눅스 대상 서버는 `keepalived(VRRP)` + `haproxy`로 가용성이 이중화되어 있어, 조치 시 **서비스 중단·HA 통신 영향이 없는 설정 변경 위주**로 수행했습니다. U-28(호스트 방화벽)은 Docker의 iptables 제어·NFS 동적 포트·VRRP 의존성을 식별하여 **NFS 포트 고정 후 노드별 순차 적용**을 권고했습니다.
